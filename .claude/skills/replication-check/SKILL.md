# Проверка сетевого кода

Игра — Listen Server, сервер главный. Пройди каждый пункт для изменённых классов и выведи пользователю список ✓/✗. Всё, что ✗, исправь до коммита.

1. **Состояние меняет только сервер.** Любая запись в игровое состояние — под `HasAuthority()` или в коде, который выполняется только на сервере (GameMode, `Server`-RPC).
2. **Клиент только просит.** Действие игрока: ввод → `UFUNCTION(Server, Reliable)` → сервер проверяет (дистанция до предмета, владелец, текущая фаза, кулдаун, не несёт ли уже предмет) → меняет состояние → репликация разносит результат. Клиент не присылает «готовые» результаты (успех задания, позицию предмета, очки).
3. **Репликация включена и описана.**
   - Actor: `bReplicates = true` в конструкторе. Физический предмет — ещё `SetReplicateMovement(true)`.
   - Component: `SetIsReplicatedByDefault(true)`.
   - Каждое `UPROPERTY(Replicated)` или `ReplicatedUsing=OnRep_X` есть в `GetLifetimeReplicatedProps` через `DOREPLIFETIME`.
   - Реакция клиента на изменение (UI, звук) — в `OnRep_X`, не в Tick.
4. **Секреты не утекают.** Задания игрока, роль Крысы, СМС-подсказки — только `DOREPLIFETIME_CONDITION(..., COND_OwnerOnly)` в PlayerState или PlayerController. Роль Параноика не реплицируется вообще до экрана итогов. В GameState и Multicast-RPC секретов нет.
5. **Класс на своём месте.** GameMode есть только на сервере. GameState — общее для всех (фаза, таймер). PlayerState — данные игрока, видимые всем, кроме полей с `COND_OwnerOnly`. PlayerController — только владелец и сервер. HUD и виджеты — только локально.
6. **Косметика отдельно от логики.** Звук, VFX, тряска камеры — через `NetMulticast, Unreliable` или `OnRep`. Логика игры от них не зависит.
7. **Данные, а не числа в коде.** Дистанции, таймеры, очки — из DataAsset или DataTable.
8. **Проверка в редакторе.** Play → Number of Players 2–4, Net Mode = Play As Listen Server, в консоли `Net PktLag=100`. Действие нужно проверить и у хоста, и у клиента: результат одинаковый, рывков нет.
